# Максим — мини-приложение для владельца

Прочитай `CLAUDE.md` целиком перед началом. Особенно раздел 9 (экраны) и 19 (факты о
платформе MAX, там же особенности библиотеки MAX UI). Здесь только твои задачи.

## Твоя зона

Правишь: `frontend/` целиком.

Не трогаешь: `backend/` (Толик и Яша).

Нужен новый эндпоинт или поле в ответе — пиши Толику. Формы ответов описаны в
`frontend/src/api/types.ts`, это общий контракт: меняешь их только по договорённости с ним.

Ветка: `feature/miniapp`.

## С чего начать

```bash
cd frontend
npm ci
cp .env.example .env     # VITE_USE_MOCKS=1 — экраны на демо-данных, бэкенд не нужен
npm run dev              # http://localhost:5173
```

Пять экранов уже собраны на демо-данных из `src/api/mocks.ts`: сводка, карточка точки,
график, задачи точки, точки и сотрудники. Они работают, но данные ненастоящие, а
редактирования нет совсем — это и есть твоя работа.

API уже готов и работает на сервере: все эндпоинты, которые вызывает приложение, отвечают в
тех формах, что описаны в `src/api/types.ts` (это проверено). Чтобы работать с настоящими
данными, в `frontend/.env` поставь `VITE_USE_MOCKS=0`. Но помни: настоящий API отвечает только
при запуске из MAX (он проверяет подпись), поэтому в обычном браузере ты увидишь заглушку
«Откройте приложение из чата с ботом». Для вёрстки держи моки, для проверки целиком —
запуск в MAX. Демо-данные на сервере: три точки, график на две недели, задачи на сегодня.

## Важно про MAX UI

Библиотека `@maxhub/max-ui` версии 0.5.0 требует **ровно** React 19.2.8, не обновляй React.
В ней нет компонентов `Panel`, `Container`, `Flex`, `Grid`, хотя документация их упоминает.
Есть: `MaxUI`, `Button`, `CellList`, `CellSimple`, `CellHeader`, `CellAction`, `CellInput`,
`Counter`, `Avatar`, `IconButton`, `Input`, `Textarea`, `Switch`, `Radio`, `Spinner`,
`Typography`. Разметку делай своим CSS в `src/styles.css`.

## Задачи по порядку

### M1. Проверка в MAX и мобильная вёрстка

Как только организаторы подключат ссылку к боту, открой приложение **в мобильном MAX и в
веб-версии** — по правилам хакатона оно обязано работать в обеих. Проверь: ширина экрана
телефона, тёмная и светлая тема, кнопка «Назад» (`useBackButton` в `src/max/bridge.ts`).
Заведи список того, что поехало, и почини.

### M2. Сводка на настоящих данных

Экран `src/screens/Dashboard.tsx`. Когда `GET /api/dashboard/` заработает: счётчики, цветовые
статусы, время последнего события, точки с проблемами наверху. Строка «2 точки из 3 без
замечаний». Переход в карточку точки по тапу.

### M3. Карточка точки

Экран `src/screens/StoreDay.tsx`: задачи дня в хронологии со статусами, кто отметил и во
сколько, кто на смене, **переключатель даты** (сейчас его нет) и **просмотр фото** по тапу
(сейчас фото не показывается). Это экран, куда ведёт уведомление владельцу, на демо он
самый важный.

### M4. График смен

Экран `src/screens/Schedule.tsx`. Сейчас это таблица только на чтение. Нужно:

- выбор недели (обычно следующая);
- **редактирование ячеек** — время начала и конца смены, пустая ячейка означает выходной;
- кнопка «Проверить покрытие» и список незакрытых окон («Чт, 17:00–22:00 — никого»);
- кнопка «Опубликовать» (сейчас она отключена);
- правка одного дня уже опубликованной недели с пересчётом покрытия.

Максимально простая таблица. **Никакого drag-and-drop** — на него уйдёт всё время, а
ценности он не добавит.

### M5. Задачи точки

Экран `src/screens/StoreTasks.tsx`: добавление, редактирование и удаление шаблонов задач.
Поля: название, тип (ежедневная или разовая на дату), плановое время, допустимая задержка,
нужно ли фото, нужно ли «Беру». Отдельная кнопка «добавить разовую задачу на дату» — сюда
владелец вносит приёмку поставки, когда узнал дату от поставщика.

### M6. Точки и сотрудники

Экран `src/screens/People.tsx`: добавление магазина (название, адрес, время открытия и
закрытия), добавление сотрудника, **показ пригласительного кода** (его владелец передаёт
человеку), деактивация уволенного. Видно, кто уже подключился к боту, а кто нет.

### M7. Обратная связь и ошибки

По критериям оценки интерфейс обязан сообщать о загрузке, результате действия и ошибке.
Пройди все экраны: везде ли есть индикатор загрузки, понятное сообщение при обрыве связи и
возможность повторить. После ошибки пользователь должен продолжить работу без перезапуска
приложения. Заготовки — `src/components/AsyncView.tsx` и `src/screens/AccessProblem.tsx`.

## Как проверять

```bash
cd frontend
npm run build      # проверка типов и сборка, обязательно перед push
```

Сборка падает — значит, в MAX приложение не попадёт: Docker собирает фронтенд этой же
командой.

## Чего в приложении быть не должно

Переписки с сотрудниками, аналитики и графиков по людям, отдельного экрана уведомлений.
Это сознательные ограничения, они защищаются перед жюри.
