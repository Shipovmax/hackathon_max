# Максим — мини-приложение для владельца

Прочитай `CLAUDE.md` целиком перед началом. Особенно раздел 9 (экраны) и 19 (факты о
платформе MAX, там же особенности библиотеки MAX UI). Здесь только твои задачи.

## Твоя зона

Правишь: `frontend/` целиком.

Не трогаешь: `backend/` (Толик и Яша).

Нужен новый эндпоинт или поле в ответе — пиши Толику. Формы ответов описаны в
`frontend/src/api/types.ts`, это общий контракт: меняешь их только по договорённости с ним.

`feature/miniapp` и `feature/reviewer-feedback` уже влиты в `main` — новую работу веди веткой
от `main`.

## Статус на 25 сентября

M2–M7 по факту сделаны — ниже описано, что именно реализовано. Открыт по-настоящему только
M1: живая проверка в MAX появится, когда организаторы подключат ссылку к боту. До этого
дальше вёрстки «на глаз» по CSS не проверить — нет ни браузерного тула, ни устройства с MAX.
Если найдёшь конкретный баг или придирку — правь точечно, не переписывай готовые экраны заново.

## С чего начать

```bash
cd frontend
npm ci
cp .env.example .env     # VITE_USE_MOCKS=1 — экраны на демо-данных, бэкенд не нужен
npm run dev              # http://localhost:5173
```

Пять экранов уже собраны на демо-данных из `src/api/mocks.ts`: сводка, карточка точки,
график, задачи точки, точки и сотрудники. Они работают, но данные ненастоящие, а
редактирования нет совсем — это и есть твоя работа.

API готов целиком и работает на сервере `https://task-controller.ru`: все эндпоинты отвечают в
тех формах, что описаны в `src/api/types.ts`. Чтобы работать с настоящими данными, в
`frontend/.env` поставь `VITE_USE_MOCKS=0`. Но помни: настоящий API отвечает только при
запуске из MAX (он проверяет подпись), поэтому в обычном браузере ты увидишь заглушку
«Откройте приложение из чата с ботом». Для вёрстки держи моки, для проверки целиком —
запуск в MAX. Демо-данные грузит `python manage.py seed_demo` (см. README, раздел
«Тестовые данные»): три точки, семь сотрудников, график на две недели, задачи на сегодня.

## Важно про MAX UI

Библиотека `@maxhub/max-ui` версии 0.5.0 требует **ровно** React 19.2.8, не обновляй React.
В ней нет компонентов `Panel`, `Container`, `Flex`, `Grid`, хотя документация их упоминает.
Есть: `MaxUI`, `Button`, `CellList`, `CellSimple`, `CellHeader`, `CellAction`, `CellInput`,
`Counter`, `Avatar`, `IconButton`, `Input`, `Textarea`, `Switch`, `Radio`, `Spinner`,
`Typography`. Разметку делай своим CSS в `src/styles.css`.

## Задачи по порядку

### M1. Проверка в MAX и мобильная вёрстка — открыто

Как только организаторы подключат ссылку к боту, открой приложение **в мобильном MAX и в
веб-версии** — по правилам хакатона оно обязано работать в обеих. Проверь: ширина экрана
телефона, тёмная и светлая тема, кнопка «Назад» (`useBackButton` в `src/max/bridge.ts`).
Заведи список того, что поехало, и почини. Это единственный пункт, который нельзя закрыть
без живого MAX — до тех пор CSS проверяется только чтением, без гарантии.

### M2. Сводка на настоящих данных — сделано

Экран `src/screens/Dashboard.tsx`: счётчики, цветовые статусы, время последнего события,
переход в карточку точки по тапу. Точки с проблемами (просрочка/невзятая → опоздание →
порядок) поднимаются наверх — сортировка на клиенте, независимо от порядка в ответе API.

### M3. Карточка точки — сделано

Экран `src/screens/StoreDay.tsx`: задачи дня в хронологии со статусами, кто отметил и во
сколько, кто на смене, переключатель даты (`DateNav`, вперёд без ограничения — карточка
строит и будущие дни по шаблонам) и просмотр фото по тапу (`PhotoView`, во весь экран).
Правка задачи прямо из списка дня, пока её итог не наступил.

### M4. График смен — сделано

Экран `src/screens/Schedule.tsx`: выбор недели, редактирование ячеек (шторка с временем
начала и конца, пустая ячейка — выходной), «Проверить покрытие» с полосой окон и списком
словами, «Опубликовать» / «Сохранить изменения» для уже опубликованной недели — правка
одного дня пересчитывает покрытие сразу. Простая таблица, без drag-and-drop.

### M5. Задачи точки — сделано

Экран `src/screens/StoreTasks.tsx` и общий `TaskEditor`: добавление, редактирование и
удаление шаблонов, поля — название, тип, плановое время, время начала окна, допустимая
задержка, «нужно фото», «нужно Беру». Отдельная кнопка «добавить разовую задачу на дату».

### M6. Точки и сотрудники — сделано

Экран `src/screens/People.tsx`: добавление и правка магазина (адрес, часы работы, выходные),
добавление сотрудника, показ и перевыдача пригласительного кода, деактивация и удаление
уволенного. Статус «в боте / ждёт привязки / уволен» виден в списке.

### M7. Обратная связь и ошибки — сделано

`AsyncView` (загрузка/ошибка/повтор на каждом экране), `ErrorNote` и `Toast` (результат
действия у форм), `AccessProblem` (заглушки не-владельца и обрыва подписи MAX) — везде есть
индикатор загрузки и способ повторить после ошибки без перезапуска приложения.

## Как проверять

```bash
cd frontend
npm run build      # проверка типов и сборка, обязательно перед push
```

Сборка падает — значит, в MAX приложение не попадёт: Docker собирает фронтенд этой же
командой.

## Чего в приложении быть не должно

Переписки с сотрудниками, аналитики и графиков по людям, отдельного экрана уведомлений.
Это сознательные ограничения, они защищаются перед жюри.
