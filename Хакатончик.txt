Мини-приложение — это интерфейс только для владельца. Всё, что делает сотрудник, живёт в боте и в приложение не попадает вообще. Пять экранов:

1. Главная — сводка по всем точкам за сегодня

Первое, что видит владелец при открытии. Список точек, по каждой:

-   название магазина

-   счётчик выполненных задач из общего числа на сегодня (например, 4/6)

-   цветовой статус: всё в порядке / есть просрочка / есть невзятая задача

-   время последнего события на точке

Сверху — общая строка: «2 точки из 3 без замечаний». Точки с проблемами поднимаются наверх списка, иначе при 10+ магазинах владелец будет их выискивать.

2. Карточка точки — день конкретного магазина

Открывается тапом по точке на главной. Здесь:

-   список задач дня в хронологическом порядке, каждая со статусом (ожидается / выполнена вовремя / выполнена с опозданием / просрочена / никто не взял)

-   по выполненным — кто отметил, во сколько, фото-подтверждение (тап разворачивает)

-   кто сегодня на смене и в какие часы

-   переключатель даты, чтобы посмотреть прошлые дни

Это экран, куда ведёт кнопка из уведомления о просрочке.

3. График смен

Таблица: сотрудники по строкам, дни недели по столбцам, в ячейке — время начала и конца смены. Пустая ячейка = выходной.

Логика работы:

-   выбор недели (обычно следующая)

-   заполнение ячеек

-   кнопка «Проверить покрытие» → список незакрытых окон: «Вторник, 20:00–22:00 — никого нет»

-   правка → повторная проверка

-   кнопка «Опубликовать»

Уже опубликованную неделю можно открыть и поправить одну ячейку — пересчёт покрытия для этого дня происходит сразу.

Для MVP это самая простая таблица, какую можно сделать. Никакого drag-and-drop — на него уйдёт всё время разработки, а ценности он не добавит.

4. Задачи точки

Редактор списка задач для конкретного магазина:

-   название задачи

-   тип: ежедневная или разовая на дату

-   плановое время и допустимая задержка

-   нужно ли фото

-   требуется ли явное принятие («Беру») — флаг для поставки и инвентаризации

Плюс кнопка добавления разовой задачи на конкретную дату — сюда владелец вносит приёмку поставки, когда узнаёт дату от поставщика.

5. Точки и сотрудники

Административный экран, нужен в основном при первичной настройке:

-   добавление магазина: название, адрес, время открытия и закрытия

-   добавление сотрудника, генерация пригласительного кода

-   деактивация уволенного

-   привязка: видно, какие сотрудники подключились к боту, а какие ещё нет

Теперь функционал сотрудника в том же формате.

1. Подключение к боту

Разовый шаг при найме. Сотрудник открывает бота, отправляет код от владельца, бот показывает, к какой точке его привязали и какие задачи за ним будут закреплены. Сотрудник подтверждает — всё, больше настроек у него нет.

2. Начало смены

Когда по графику начинается смена, бот пишет сам: что сегодня за точка, какие задачи и во сколько. Сотрудник ничего не запрашивает — список приходит автоматически.

3. Отметка задачи

Основное и почти единственное действие. За несколько минут до планового времени приходит напоминание с кнопкой. Сотрудник нажимает «Выполнено», при необходимости присылает фото, получает подтверждение с зафиксированным временем.

4. Принятие задачи на себя

Для задач с флагом «Беру» — поставка, инвентаризация, пересчёт кассы. Бот спрашивает всю смену, кто принимает; первый нажавший закрепляет задачу за собой, остальные видят, что она занята. Дальше — обычная отметка.

5. Проверка своего статуса

Сотрудник может в любой момент спросить у бота, что осталось на сегодня. Бот отвечает списком с отметками. Если смена не идёт — показывает соответствующее состояние: выходной, смена ещё не началась, смена закончилась.

6. Конец смены

Бот присылает итог: сколько задач закрыто, что осталось. Это не требует действий, просто фиксирует результат.
